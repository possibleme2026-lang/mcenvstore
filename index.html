Status Quo

How environments are made today

However smart a model is, if it's only trained on a handful of fixed tasks, it won't learn the long tail of the real world.

Synthesized in-house

Engineers write scripts and build synthesis pipelines to generate training environments. Coverage is limited by team size and domain knowledge — no matter how strong the pipeline, it can't cover the real long-tail tasks across every industry.

Procured from vendors

Custom-built per requirement, paid per project. No matter how large the data vendor, they don't know what tasks are actually worth training in every industry, every company, every niche software product. Long cycles, high cost, unpredictable quality.

Chasing an infinite distribution of tasks with finite labor — that's the fundamental contradiction.

As long as environments are produced by "a few people deciding what's worth training for everyone," the ceiling of agent capability will always be locked within the horizon of those few.

Platform Capabilities

What the platform does

These are things model companies would otherwise build themselves. We believe they should be platform-level infrastructure, not wheels reinvented by every company.

01

Automated Verifier Generation

Upload a task and describe "what counts as done." The platform auto-generates a verifier based on task type. Contributors only need to confirm or fine-tune — no coding from scratch.

Code tasks → tests from reference impl. Rule-based → criteria to executable checks Document tasks → rubric from expected output Open-ended → grouped rubric from references
02

Anti-Cheating Audit

Once an environment is public, models will try every trick to cheat — it's an arms race. Every environment runs through a "Hack Agent" before launch to auto-detect vulnerabilities. Fix what can be fixed, delist what can't. Trajectories are continuously audited during training.

Answer leak detection Irrelevant action bypass Plausible-wrong construction In-training trajectory audit Cheating reward zeroing
03

Grader as a Service

Binary pass/fail isn't enough. Two grading modes: GRS with task-specific rubrics for offline synthesis, and GAR with online pairwise comparison and advantage redistribution. Model companies just call the API — no implementation needed.

GRS — offline rubric grading GAR — online pairwise comparison Advantage redistribution Unified API access
04

Isolation & Standardization

Every environment runs in its own container with a unified Gym interface — resettable, reproducible, versioned. Network isolation, file isolation, and resource quotas are all default.

Containerized isolation Unified Gym interface Resettable / Reproducible Version management Resource quotas

Contributors only need to do one thing: describe the "obvious" work they do every day. The platform handles the rest — verifiers, anti-cheating, graders, isolation, standardization.

A Lighter Way to Contribute

MCEnvstore MCP

Put the environment collector inside the agent tools you use every day. You do nothing extra — just use agents normally — and you might contribute a real long-tail environment with verification signals.

Just add one line of MCP config to any agent product — Codex, Cursor, Claude Code, MiMo Code, and more — then work as usual.

MCP listens quietly in the background without interrupting. It only flags "high-value fragments" — many back-and-forths with the agent, you correcting its mistakes, you finally saying "that's it, looks good."

It packages the workflow into a local environment draft — what the task is, initial state, what actions the agent took, what feedback you gave, what counts as done — then runs local anonymization.

Company names, project names, person names, emails, API keys, real financial numbers — all replaced with placeholders. Structure preserved, sensitive values replaced.

After anonymization, you get a preview. Upload only when you click "Confirm contribution" — choose "Ignore" and it disappears locally.

mcp.config.json 
// Add to your agent config
{
  "mcpServers": {
    "mcenvstore": {
      "command": "npx",
      "args": [
        "@mcenvstore/mcp-server",
        "env"
      ],
      "env": {
        "MCENVSTORE_API_KEY": "your_key_here",
        "CAPTURE_MODE": "suggest"
      }
    }
  }
}

Long Tail Value

Why everyone should participate

Model companies can only hire so many domain experts. But the world has practitioners in every industry, internal processes at every company, users of every niche software, and localized tasks in every region.

Common tasks Long-tail tasks

A single financial reconciliation environment contributed by an accountant may be more valuable than a hundred generic finance tasks synthesized by a model company.

Incentives

What contributors get

Like creator revenue sharing on content platforms — you contribute environments, the platform distributes them to those who need them, you earn. And high-quality environments don't decay in value quickly over time.

💰

Revenue Sharing

When model companies train on environments you've contributed, the platform tracks usage. Tokens paid by model companies are proportionally distributed to contributors. The more useful and consumed your environment, the more you earn.

⭐

Reputation Points

High-quality environments earn community ratings and reputation points, increasing your influence on the platform. Top contributors gain early environment review rights, beta access to new features, and more.

🔑

Access Rewards

Contributing environments earns you access to other environments, or priority testing access to new models. The more you contribute, the more resources you can use — a positive feedback loop.

More cumulative than video

On content platforms, video traffic decays quickly over time. But high-quality environments can be reused, iterated on, and composed. A well-validated environment may keep appreciating as more models consume it.

Every user is an environment collector

With MCP, a million users means a million environment sources. Every correction, every debugging session in your normal agent use could become a valuable environment for someone else's model training.
